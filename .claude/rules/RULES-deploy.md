## Deploy Rules (newest at top)

**DEP-5: REDIRECT ON ANY URL CHANGE — PERMANENT (2026-06-26):**
Any time an HTML file moves to a different path (restructure, rename, folder change),
add a 301 redirect in _redirects at repo root BEFORE the move is live.
Format: /old-path.html    /new-path.html    301
Never move a page without a redirect — breaks bookmarks, Google index, and Airtable links.
// Justification: Session A (daje restructure) — old product URLs would 404 without _redirects

**DEP-4: WORKER REPO_MAP IS THE DEPLOY ROUTER — PERMANENT (2026-06-25):**
All content deploys route through the Cloudflare Worker REPO_MAP.
Adding a new site requires a new REPO_MAP entry — not a new deploy mechanism.
Current map (as of 2026-06-25): BUS01 (iflex), BUS02 (daje), BUS03 (jade), BUS04 (flow).
// Justification: centralised routing — one worker controls all content pipelines

**DEP-3: CLOUDFLARE PAGES AUTO-DEPLOY — PERMANENT (2026-06-25):**
All sites deploy via Cloudflare Pages auto-deploy on push to main branch.
No manual deploy steps required or permitted.
Deploy pipeline: Airtable → GitHub Action → commit to main → Cloudflare auto-deploys.
// Justification: manual deploys create version drift — auto-deploy is the only path

**DEP-2: SCRIPT-OWNED FILES ARE IMMUTABLE — PERMANENT (2026-06-25):**
Files generated by generate_*.py scripts must never be manually edited.
Manual edits are overwritten on next workflow run.
Script-owned files per repo:
  i-flexthailand.com: blog/*.html, th/blog/*.html, product/*.html, th/product/*.html,
    blog-listing.html, product-listing.html, th/blog-listing.html, th/product-listing.html,
    gallery-data.json, news-data.json, testimonials-data.json, products.json
  janishammer-home: blog/post-*.html, th/blog/post-*.html
  daje-queencatcher: product/*.html, th/product/*.html, products.json
  jade-coffee: product HTML pages (when generated), products.json
  janis-flow: product/*.html, th/product/*.html, products.json
To change output: edit the generator script — never the output file.
// Justification: manual edits to generated files cause silent data loss on next workflow run

**DEP-1: SECRETS IN GITHUB SECRETS ONLY — PERMANENT (2026-06-25):**
AIRTABLE_TOKEN and AIRTABLE_BASE_ID must only appear in GitHub repo Secrets.
Never in any .py, .js, .html, .yml, or .md file — not even in comments.
// Justification: all repos are public — anything in source is publicly readable; scan confirmed compliance
